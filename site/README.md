# Subsigmoid web front end

HTML/JS with a small Python server, no build step or third-party server dependencies.

- `index.html`: front page
- `app.html`: teacher dashboard (course, exam, student, live session, import)
- `quiz.html`: the quiz people take on their phones
- `method.html`: how the statistics work

Run it locally:

From the repository root, run `python3 server.py`, then open
http://localhost:8771/app.html.

The server reads `.env` at the repository root (or environment variables, which take
precedence). Copy `.env.example` to `.env` and set `DATABRICKS_HOST`,
`DATABRICKS_TOKEN`, `DATABRICKS_JOB_ID`, and `DATABRICKS_TASK_KEY` for the assessment
notebook task. The host is the workspace URL; a trailing `/api/2.0` is also accepted.
The notebook must run with `return_json=true`, as supported by `notebooks/assessment.ipynb`.
Keep `.env` private (`chmod 600 .env`); it is ignored by Git and outside the public `site/` directory.

The connected dashboard reads the latest successful assessment job run. It shows
student/question/response counts, model status, and at most three questions with
the lowest average scores. The server sends only these fields to the browser;
student records, rubric details, embeddings and credentials stay on the server.
Results are cached for 30 seconds; Refresh checks for a newer result after that
window. Reading the dashboard never launches a job. It shows connection errors
with a retry button instead of substituting sample data.

With no Databricks configuration, the original demo uses sample data from `data/`
through `js/api.js`. A static-only preview still works with
`cd site && python3 -m http.server 8771`. The full course/exam/student/quiz backend
contract remains in `API.md`; its explicit meta tag or `?api=` configuration still
works separately. The Databricks summary does not implement those demo workflows.

`server.py` binds to localhost by default. For hosting, run it behind your
authenticated HTTPS service and supply credentials through server environment
variables. Static hosting alone cannot provide the private Databricks connection.

Checks (from the repository root):

```bash
python3 -m unittest discover -s tests -v
node --test tests/dashboard.test.js
```

Code map: `extract.py` reads Gradescope PDFs locally; `notebooks/extract_databricks.ipynb`
does extraction in Databricks; `notebooks/assessment.ipynb` analyzes CSV rows;
`server.py` adapts its Jobs API output; `js/api.js` fetches it; `js/app.js` renders it.

Sample data is generated by `../tools/make_sample_data.py`. Brand assets (logo, icon) are in `../brand/`.
